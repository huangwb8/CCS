# CCS 0.8.6 目标函数扩展验证

本轮只使用代码生成的合成输入。CCS 的目标版本严格采用负责人指定的 **0.8.6**；没有创建 tag 或执行远程发布。实际入口与逐例结果见 [目标函数报告](objective-report.html)及[复现说明](README.md)。

## 接口与兼容性

新增末尾参数 `norm_objective`，支持 `median`、`cohort_median`、`mean`、`lower_tail`、`mean_lower_tail`。默认值、旧位置参数、旧 `Raw`／`Summary` 表结构和默认 Repeat 保持兼容。四种新策略排除 pooled `All`，评分列与遗留中位数分开，避免下游误读。

修改前冻结了 0.8.5 的合成输入与 64 组输出：穷举覆盖 K=2/3/4、四种排序、两种 ROC；DP 另覆盖 K=5 和 K=M。默认调用及显式 `median` 都与冻结结果一致，容差为 `1e-12`，比较完整表、切点、候选和确定性诊断，仅排除耗时。冻结文件及旧函数位于 `reference/`。

正式质量基准为 M=10，C=4/5，十个固定种子，K=4/5/6，五种目标及两种 ROC，共 **600 例**。其中 **592 例**在 `1e-10` 内匹配同目标穷举最优值，**594 例**的差距不超过工程比较尺度 `0.005`。四种新策略的 Raw 模式均匹配穷举；六个超出比较尺度的案例全部来自 `OptimizeRank`，最大差距为 **0.027469127850857**。

全部案例保存在 `products/objective-quality.csv`。六例的进一步诊断见 `objective-gap-diagnostics.csv`：精修均已收敛，任意一／二边界改变都不能严格改善；当前最佳切分与最近全局最优切分相差 3–4 个按序对应的边界。该距离不证明必须一步改变这些边界，也不排除同分平台或多步路径。本次按计划保留初值集合、最多六个起点和十轮上限，完整报告近似局限。

六例的穷举最优切分还单独经过原 ROC 逐队列核对，快速 AUC 及独立汇总的目标值均在 `1e-10` 内一致。

## 新旧实现的直接计时

M=12、C=4，K=4/5/6，两种 ROC，每组重复三次，分别运行冻结 0.8.5／当前实现的默认 DP 和穷举，共 **72 次**。计时在大规模计算结束后单独执行。旧／新相同搜索的最优分数、映射、候选数及评分提案数全部通过一致性断言。

各组配对耗时比的中位数显示，当前默认穷举／DP 的加速比为 **30.54–64.77 倍**；目标扩展后的默认 DP／旧默认 DP 为 **1.00–1.13**。前者主要反映既有 DP 避免枚举的收益，后者反映本次评分抽象的兼容成本，不能把两者合并为这次新增目标带来的加速。原始每次测量见 `products/objective-timing.csv`，分组中位数由 Rmd 自动计算。

## 报告与运行环境

这是已有 simple 场景测试，没有补建 renv 或 targets，也未更改真实队列分析的 DAG 和 store。`objective-smoke.R` 用同一基准与渲染入口执行较小合成输入，断言产品 schema、分数范围、目标非下降、HTML／PDF 生成，以及正式产品、代码与 raw 未变化。每次现场位于独立的 `tmp/tests/norm-objectives-*`；有效现场以其中 `verification.json` 为准。

报告只消费 CSV，统计值通过 inline R 生成；固定合成问题和本机计时采用描述性比较，不计算总体置信区间或 p 值。报告按 nsfc-humanization 检查表达，保护 R chunks、inline R、数字、目标定义及科学结论，并人工复核代码生成的解读。启发式文本检查会把版本号、固定公式常数和 R 生成段落标为待核对，未将这些提示当作科学验证。

Windows CLI 使用有效的 UTF-8 locale 完成最终安装与验收：`LC_CTYPE=English_United States.utf8`、`LC_COLLATE=C`，清空不受支持的 `LC_ALL=C.UTF-8`。早期曾遇到 worker 的 `VirtualProtect` 启动错误、无效 locale 下安装后的字符串异常，以及隔离测试期间正式产品变化导致的断言失败；这些现场未算作通过，修正环境与执行顺序后重跑，失败和最终日志均保留。
