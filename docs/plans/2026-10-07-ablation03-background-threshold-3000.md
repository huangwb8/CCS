# ablation-03 共同秩背景门槛修订计划

## 问题与目标

增殖 gene signature 的选定高覆盖合同保留 4,848 个共同背景基因，因原有 5,000 基因门槛未产生秩主结果。负责人在查看该结果后明确要求把共同背景门槛降为 3,000，重新计算并交付同步的 Rmd/HTML。这相当于调整测量资格：实际使用的背景仍是入选队列的完整基因交集，不抽取或截断为 3,000 个基因。

## 修订范围

高覆盖验证与全队列根因诊断两份配置统一采用 3,000；signature 覆盖率、队列搜索、人数、完整背景有限值、reference 支持、top-15、随机种子与固定五项 BH 检验族保持既有设计。搜索预算中的 5,000 是检索参数，不属于背景门槛。

修正分析 wiring 中含固定旧阈值的状态标签，并让报告按配置解释失败原因。CCS 包源码、版本、正式输入及原广队列基线保持不变。旧计划中的 5,000 门槛保留为历史设计，本次负责人授权覆盖该条规则。报告说明此次修订发生在观察原结果之后，不能称为最初预设的 3,000 门槛，也不承诺所有覆盖档位都会通过。

## 实施与验收

1. 保存原门槛下的聚合主结果、覆盖率及读取器结果作为比较证据，记录正式科学输入和原基线哈希。
2. 更新配置、状态标签、报告、README 和 Unreleased；在隔离合成数据上执行同一 DAG，核对 2,999/3,000 基因边界、完整背景评分、五项 BH 族及 HTML。
3. 按结构与数据流、R 实现与恢复、科学与统计顺序完成三个独立只读审查；通过后使用正式 cache root 的 `_targets.R`、crew 与 `tar_make()` 重算受影响节点。
4. 核对五项选定主结果是否可估计、其有效人数及来源广度；完整保留 80 个评分/候选池/覆盖率格子和不可估计原因。比较原可估计项的效应与区间，独立重新计算 BH q 值。报告同步所有门槛、图表和结果解读，核验原广队列基线、输入与包版本未变，并验证 BAC 哈希链。

## 推断边界

主要估计对象仍是同一患者两臂 top-15 邻居表达接近度差（d1−Direct），先队列内平均再队列等权，使用 95% cohort bootstrap 与既有双侧配对符号翻转检验，五项选定 signature 构成固定 BH 族。读取器 MAE 差沿用 reference-only 训练及相应固定五项族。资格扩展可能改变有效人群和 q 值；CI 跨零不证明等价，负差不直接证明纯生物信息丢失。

已知增殖 60/70/80% 合同背景不足 3,000，而全队列诊断共同背景约 1,130。它们仍可能不可估计；降低门槛不会补足缺失测量。

## 验收结果

2026-10-07 正式 `tar_make()` 成功退出，使用 `D:/cache/ccs/_ablation-03/targets`，完成 86 个节点或分支、复用 22 项；Rmd/HTML 和配套聚合表、PDF 已同步。五项选定主比较均可估计，完整 80 格及不可估计原因保留，主表与完整表的主比较 q 值一致。

增殖仍使用 90% 合同、14/15 个 signature 基因及全部 4,848 个共同背景基因，实际有效人数为 14 个队列、5,211 个 query。同癌种邻居接近度差（d1−Direct）为 −0.014185，95% cohort bootstrap CI [−0.026054, −0.000056]，原始 p=0.062256、固定五项 BH q=0.155640。五项主比较均未达到 q<0.05；区间低于零不代替校正检验，也不证明全部生物信息丢失。增殖秩 ridge 与 XGBoost 的标准化 MAE 差分别为 0.023878、0.028433，区间均跨零。

原四项可估计主效用的效应、区间、原始 p 值与人数逐项复现；原 18 项可估计读取器结果的相同字段也复现。32 个输入、原基线、包源码和 store 配置哈希及九个核心科学 target 的时间与数据哈希保持不变，冻结合同的基因、队列、背景数量及选定档位未变。正式报告及依赖的 `tar_outdated()` 返回空集，没有 target 错误。

隔离同 DAG 合成验收和三轮独立串行审查通过；2,999/3,000 边界、完整背景有限值、配置传播和增量恢复均已验证。人工核对正式覆盖率图与五项主效应图，增殖已展示、背景虚线使用修订门槛。运行警告包括既有包构建版本、XGBoost 的冗余 `seed` 参数和资源日志残片；读取器已经显式调用 `set.seed()`，未出现科学 target 错误。验证证据位于 `.bensz-api/task-20261007-1902-background-3000/shared/`，不记录患者级数据。
