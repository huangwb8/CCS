# ablation-03 正式生物缓存失效与恢复计划

## 通俗解释

正式分析把一份以前准备好的生物数据当作这次实验的现成材料，但它的登记信息与当前实验不符，计算因此停在生物分析。就像包裹里的物品看起来齐全，收件名单和装箱记录却与本次订单不一致：不能只凭件数相同就签收。修复后，只有名单与来源均核对通过才使用现成材料；不通过就从同一批授权原始资源重新准备，而不是修改登记信息掩盖差异。

## 已确认的问题与漏检原因

- 2026-09-23 18:38，正式 `biology_analysis` 因预计算生物缓存的样本键不符而使 `tar_make()` 中止；上游 `representation_analysis` 已完成，后续三份 HTML 尚未直出。
- 正式输入包含预计算生物和结构字段。缓存实际覆盖当前 38,547 个样本，但样本键校验不通过，生成脚本的校验值也与当前脚本不符；样本覆盖率不能代替缓存来源验证。原始表达图谱与基因签名均可访问，但表达图谱约 5.6 GB，重新计算有内存与时间成本。
- 隔离验收的 `make-input.R` 明确将 `biology_inputs`、`structural_inputs` 设为 `NULL`，从小样本重新生成缓存。因此它验证了重新计算的分支，没有触及正式输入中“直接复用预计算缓存”的分支；先前的测试结论不能外推到该分支。
- 2026-09-23 19:22，续跑又在 `representation_report` 中止：`rmarkdown` 2.26 对带空格的 Rmd 文件名尝试在同目录复制一个净化名称的副本；上次失败遗留的同名副本已存在，于是拒绝覆盖。该副本哈希与源 Rmd 一致，但不应删除或覆盖来掩盖重试缺陷。生物输入并行重建随 `tar_make(error = stop)` 被取消，不代表表示分析失效。
- `exam-20260923-01` 的输入制作只覆盖小样本计算，既没有正式预计算缓存，也没有预先遗留的同名 Rmd 净化副本；报告目标的旧测试只检查 targets 连线，不实际渲染失败后的重试场景，因此两类故障均未检出。
- 2026-09-23 19:34，续跑完成生物输入、生物分析和三份报告后，独立的 `structural_analysis` target 因无法解析 CCS 包的内部尺度变换函数中止。结构脚本先前把 helper 加载进全局环境；单独的 targets worker 不会继承小测脚本中 `source(R/ablation.R)` 所留下的全局函数。隔离验收运行过结构阶段，但其进程加载顺序掩盖了这一隐式依赖。修复为将结构 helper 加载到当前 target 环境，并从已安装的 CCS 命名空间显式绑定所需的两项内部变换；新增隔离作用域回归检查。

## 目标与改进方向

- 在正式 targets 图的 `biology_inputs` 边界核验预计算缓存是否符合当前表示样本、生成脚本及必要的来源约定；不符时改由现有生物输入准备 target 从授权原始资源重新生成，而非继续复制失效缓存或仅改写哈希。仍只通过 `_targets.R` 与正式 store 执行，不使用旁路 runner。
- 增加小型回归测试，分别覆盖失效预计算缓存触发重建、合格缓存可以复用，以及隔离小测原有的无预计算分支；测试不读写真实基因组数据。
- 不改科学参数、原始正式输入快照、CCS 包版本或用户已有数据。目标仅是纠正缓存复用判定，并复用已完成的表示计算成果。
- 报告渲染用同一项目目录下唯一、无特殊字符的临时 Rmd 输入，使相对模板路径保持不变，仍直接生成原名 HTML；仅清理自己创建的临时输入，绝不碰历史遗留副本。用一个留有净化副本的微型 Rmd 实测失败前后行为以及 HTML 输出路径。

## 恢复顺序与验收

- 先运行应失败的回归测试，再实施最小修复并使测试通过；复核代码和现有验收记录，确认缓存失效时只重建生物输入，不误触发耗时的表示分析重算。
- 从正式 targets store 续跑 `tar_make()`，用同一 store 的 `tar_watch()` 和 worker 心跳观察。检查新生物缓存的样本键、脚本与来源一致性；资源不足或源文件校验失败即停止，不能降级科学边界。
- 只有全部 16 个 target 无错误、四份 Rmd 对应的 HTML 均由 file target 直出且非空、资源观测可用、定向测试与 BAC 校验通过，才宣告正式分析完成。失败时保留 targets store、错误日志和已有成果，由同一正式图按失败边界恢复。
