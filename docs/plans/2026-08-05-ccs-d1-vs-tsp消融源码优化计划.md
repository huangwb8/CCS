# CCS d1 vs GSClassifier-TSP 消融实验与源码优化计划

## 一句话说明这次要做什么

这次消融实验只回答一个问题：

> 同一个样本，直接使用 GSClassifier 生成的原生 TSP 特征，与先经过 150 个冻结 cohort models 得到 d1 相比，d1 到底改善了什么，又牺牲了什么？

实验在 d1 这一层停止。d2、d3、metaCCS、normCCS 和 ICI response 都不参与判断 d1 是否更好，因为这些下游步骤各自还有 UMAP、聚类、映射和任务模型等大量超参数。把它们混进主实验，会让结果无法明确归因于 d1。

## 用一个简单比喻理解两条路线

可以把 GSClassifier 原生特征看成患者的“原始答题卡”，把 cohort models 看成来自不同队列的“老师团”。

```text
同一份表达数据
      ↓
GSClassifier 原生处理
Xbinned + Xpairs + Xset
      ↓
完整 GSClassifier-TSP 输入
      ├── 直接使用 ──────────→ Direct-GSClassifier
      └── 交给冻结老师团评议 → Cohort-d1
```

两组使用相同样本、相同表达数据和相同 GSClassifier 特征。唯一主动改变的是：有没有经过冻结 cohort bank。

| 实验组 | 实际内容 | 通俗解释 |
|---|---|---|
| `Direct-GSClassifier` | GSClassifier 原生特征矩阵 | 直接阅读原始答题卡 |
| `Cohort-d1` | 所有冻结 cohort models 的 probability blocks | 汇总老师团对答题卡的判断 |

当前真实模型的 Direct-GSClassifier 输入共有 529 个特征：

- 32 个 single-bin；
- 496 个 gene-pair；
- 1 个 set-pair。

因此，496 个二元 gene-pair 不能单独代表正式基线。`prepared$direct` 才是主实验输入；`prepared$tsp` 只保留作 feature-type 和兼容性审计。

## 为什么这样比较最公平

若 Direct-GSClassifier 和 Cohort-d1 使用不同样本、不同训练折、不同模型复杂度或不同调参次数，即使 d1 获胜，也不能证明胜因来自 cohort bank。

本实验固定以下条件：

- 同一批 sample IDs；
- 同一 GSClassifier 版本、`geneSet`、`breakVec` 和 feature manifest；
- 同一组训练 cohort 和测试 cohort；
- 同一组随机种子和训练子集；
- 同一种低复杂度任务模型；
- 同一套候选超参数和相同计算预算。

但两种表示可以在各自的训练数据中选择适合自己的最佳正则化参数。强迫它们使用同一个 `lambda` 并不公平，因为两种表示的尺度和有效维数不同；让某一组搜索更多模型也同样不公平。

## 实验开始前必须先确认什么

### d1 不能提前看过测试样本

最理想的评价样本是完全没有参与 cohort bank 训练的外部样本。也可以使用严格 out-of-fold 生成的 d1。

每个样本的 d1 来源要明确记录为：

- `external_frozen`：完全外部样本，使用冻结 bank 计算；
- `out_of_fold`：样本没有参与产生自身 d1 的训练；
- `in_sample`：样本参与过相应模型训练；
- `unknown`：无法确认。

只有前两类可以支持确认性结论。若是 `in_sample` 或 `unknown`，代码可以描述 d1 怎样改变空间，但不能声称 d1 能泛化到新 cohort。

### 生物学标签不能来自 d1 自己

判断 d1 是否保留真实生物结构时，不能拿 metaCCS 等由 d1 产生的标签反过来证明 d1 正确。

标签应分成三类：

| 标签角色 | 含义 | 能支持多强的结论 |
|---|---|---|
| `bank_aligned` | cohort models 已经使用或高度接近的训练目标 | 只能说明 d1 保留了自己的训练方向 |
| `independent` | 没有参与 d1/metaCCS 构建的样本级生物标签 | 可以检验 d1 是否保留独立生物结构 |
| `technical` | cohort、assay、platform 等技术来源 | 用来检查技术偏差是否减弱 |

若只有 tissue，而 tissue 又与 cohort 高度重合，实验最多只能作描述性分析。要形成强结论，至少需要一种跨多个 cohort 分布、且在 cohort 内也会变化的独立生物标签。

## 具体怎样做消融实验

### 先看 d1 到底改变了什么

这一步不判断谁更好，只比较同一批患者在两种表示中的远近关系。

要做的计算包括：

- 两种表示的样本距离顺序是否相似；
- 每个患者的近邻有多少重合；
- 哪些原本接近的患者被 d1 推远；
- 哪些原本较远的患者被 d1 拉近；
- d1 的差异是否主要由少数 cohort modules 或较宽的 blocks 支配；
- d1 是否存在大量重复、坍缩或无效方向。

为什么要先做这一步：

> d1 与输入不同，只能说明 cohort bank 改写了表示；随机投影和噪声同样可以让空间变得不同。只有改变具有正确方向，才可能是进步。

距离计算不能再假定整个 Direct-GSClassifier 矩阵都是二元特征：

- Direct-GSClassifier 保留 `trainDataProc_X()` 产生的 single-bin、gene-pair 和 set-pair；主分析在 reference/train 边界内做列标准化，再计算 Euclidean 距离。
- 仅针对 496 个 gene-pair 的 Hamming 距离可以作为 feature-type 敏感性检查，但不是正式主空间。
- d1 若确认每个 block 都是概率向量，则按 module 等权聚合 Hellinger 距离，避免输出列更多的 module 自动占更大权重。

### 再看这种改变是否有生物学方向

每次完整留出一个 cohort，把它当成新来的 query cohort；其余 cohorts 组成 reference atlas。

对 query cohort 中的每位患者，分别在 Direct-GSClassifier 和 Cohort-d1 中，到 reference atlas 寻找近邻，然后比较：

- 找到的近邻是否具有相同的独立生物标签；
- 生物学不同、但原本很接近的患者，是否被 d1 合理推远；
- 生物学相同、来自不同 cohort 的患者，是否被 d1 保留或拉近；
- 稀有癌种、小 cohort、不同 assay/platform 是否受到损伤；
- 最差 cohort 是否出现明显退化。

这样做还有一个重要原因：当前代码在单个 held-out cohort 内计算 `cohort_mixing`。测试折只有一个 cohort，所以该指标默认必然等于 0，也不存在“同 biology、跨 cohort”的测试折内近邻。正确做法是让 held-out cohort 到其它 cohorts 中找邻居。

主要报告：

- top-k 生物标签一致率；
- mean reciprocal rank，即正确生物近邻出现得有多靠前；
- 跨 cohort 生物近邻保留率；
- 逐 query、逐 cohort 的 `Cohort-d1 - Direct-GSClassifier` 配对差值；
- 稀有组、平台组和最差 cohort 的结果。

只有 d1 提高跨 cohort 生物检索，同时没有抹平独立生物结构，才可以说 d1 改善了表示。单独提高 cohort mixing 不能算成功，因为把所有患者混成一团也会得到很高的 mixing。

### 检查 d1 是否让有限样本更容易学习

这是最能体现 d1 科研价值的实验。

d1 是 GSClassifier 原生输入的确定性变换：

$$
Z_{GSC}=G_{GSC}(E; geneSet, breakVec, feature\ manifest),
\qquad d1=F(Z_{GSC}).
$$

因此，d1 不可能凭空创造输入中不存在的信息。它真正可能带来的价值是：重新组织和压缩信息，让有限样本、简单模型更容易学到跨 cohort 稳定规律。

验证方式：

- 外层每次完整留出一个 cohort，用来模拟真正的新 cohort；
- 内层继续按 cohort 分组，只在训练 cohorts 中选择正则化参数；
- 两组使用同一种低复杂度模型，优先复用 deterministic linear XGBoost；
- 两组使用相同 `lambda` 网格、迭代上限、类别权重规则和计算预算；
- 标准化、缺失处理、低方差过滤和校准都只能在训练边界内完成；
- PCA 不作为主分析的必经步骤，避免再引入一个影响结论的 rank 超参数。

除了使用全部训练数据，还要画配对学习曲线。例如只使用 10%、25%、50% 和 100% 的训练 cohorts/样本，观察两组表现怎样变化。

主要问题不是“谁的最高分更大”，而是：

- d1 是否用更少训练样本达到相同性能；
- d1 的小样本优势是否随样本增加而消失；
- d1 是否只提高平均值，却损害最差 cohort；
- d1 是否只对 bank-aligned 标签有效，对 independent 标签无效。

如果 d1 只在小样本时占优，样本足够多后与 Direct-GSClassifier 收敛，正确结论是：

> d1 改善了样本效率或归纳偏置，而不是增加了原始信息量。

### 最后检查 d1 牺牲了什么

d1 是压缩和重组，不可能只谈收益、不谈损失。

需要从三个方面检查代价：

- **输入信息损失：**尝试从 d1 重建完整 GSClassifier 输入。gene-pair 用 balanced accuracy/Brier，single-bin 用有序一致性，set-pair 用相关性或重建误差。
- **生物信号偏向：**分别比较 bank-aligned 与 independent 标签。如果 d1 只改善训练目标，却损害独立 subtype/pathway 或稀有类别，应写成“有方向的信息压缩”。
- **贡献过度集中：**检查结果是否主要由少数大 cohort、宽 block 或单一 tissue bank 驱动。若是，不能把收益写成广泛的 cohort congress 效应。

第一版不强行加入原始表达扰动、缺失基因和跨平台技术重复，因为这些实验需要重新执行冻结 bank。当前 `ablation()` 只读取已经生成的 d1；在没有可靠 re-encoding/cache 合同前，不能用占位结果假装完成鲁棒性验证。

## Null 对照有什么作用

Null 只用于排除假解释，不负责决定主结论。

| 对照 | 怎样生成 | 排除什么解释 |
|---|---|---|
| `Null-RP` | 随机重组 Direct-GSClassifier 输入 | 是否随便投影一下也能产生类似改善 |
| `Null-Perm` | 在 cohort 内打乱 d1 blocks 与患者的对应 | d1 收益是否依赖正确的患者级证据组合 |
| label permutation | 在 cohort 内打乱生物标签 | 调参和评估流程是否会在无信号时制造优势 |

如果某个标签在 cohort 内完全不变化，`Null-Perm` 对该标签没有检验能力，必须标记为 `not_eligible`，不能进入结论或自动 Gate。

## 怎样保证统计结论不夸大

- 每个 query 样本先得到两组的配对差值；
- 同一 cohort 内的随机重复先平均；
- 最终以 cohort 为统计单位做 paired bootstrap；
- 不把上万个样本或几十个随机种子伪装成上万个独立重复；
- 同时报告平均 cohort、最差 cohort 和可估 cohort 数；
- 最小重要差异由项目负责人在看结果前指定，源码不把 `0` 当作默认科学阈值；
- 不把多个指标加权成事后“综合冠军分”。

## 什么结果允许得出什么结论

| 真实结果 | 通俗解释 | 允许的结论 |
|---|---|---|
| d1 的跨 cohort 生物检索更好，小样本学习更快，独立标签、稀有组和最差 cohort 没有重要损伤 | 老师团确实让信息更容易被利用 | 支持 cohort bank 提供有价值的归纳偏置和样本效率改善 |
| d1 只让空间变得不同，但生物检索和学习曲线没有改善 | 老师团改写了档案，但没有带来可验证收益 | 不能支持 cohort bank 的必要性 |
| d1 改善 bank-aligned 标签，却损害 independent 标签或稀有组 | 老师团偏向自己熟悉的问题 | d1 是有方向的压缩，必须公开适用范围和代价 |
| d1 与 Direct-GSClassifier 基本等价 | 老师团没有提供足以抵偿复杂度的增益 | 按 KISS 优先更简单的 Direct-GSClassifier |
| d1 更差，或接近随机/置乱对照 | 压缩、重权重或噪声造成的损失超过收益 | 应收紧 CCS 核心主张并检查 cohort model 质量 |
| d1 来源不明或测试样本参与过 bank 训练 | 无法排除记忆训练数据 | 只能报告描述性几何，不能声称跨 cohort 泛化 |

## `R/ablation.R` 具体怎样改

### 保留现有正确部分

- 保留 `.ablation_frozen_feature_manifest()`：从冻结模型恢复实际使用的完整 feature support。
- 保留 `.ablation_gsclassifier_matrix()`：使用 `GSClassifier::geneMatch()` 和 `trainDataProc_X()` 重建原生输入。
- 保留 `prepared$direct` 作为正式 Direct-GSClassifier 基线。
- 保留 module block、样本、feature、配置和 seed 的 hash 审计。
- 保留按 cohort 分组的外层验证思想。

### 优先修正当前硬问题

- 不再把 `prepared$tsp` 提升为主实验组；它只记录 ordinary gene-pair 子集。
- 把含混的 `Direct` 组名改成机器可读的 `Direct-GSClassifier`。
- 重写跨 cohort 邻域指标：held-out cohort 是 query，其它 cohorts 是 reference。
- 删除或修正只写入标签、实际始终 Euclidean 的 `distance` 参数。
- `biology = tissue` 只能作为可运行回退值，输出必须明确其证据等级不足。
- `Null-Perm` 在标签不合格时自动返回 `not_eligible`。
- 修正 finite grouped-fold 的负载与标签覆盖分配。
- 把导出函数内的 `if (FALSE)` 合成夹具迁移到 `test/ablation/`。

### 收紧公共入口

推荐让 `ablation()` 默认只运行 `representation`：

- 旧名称 `cohort` 暂时映射为 `representation`，并给出 deprecation 提示；
- `scaling`、`tissue_first` 和 `metaccs` 不再默认执行；
- 是否彻底删除旧选项属于公共 API 的破坏性决定，由项目负责人确定版本和时间；
- 在正式删除前，可以把下游遗留实现移到明确标记为 exploratory/legacy 的独立模块。

参数按研究问题组织：

| 参数域 | 负责什么 |
|---|---|
| `comparison` | Direct-GSClassifier、Cohort-d1 与原生 feature contract |
| `provenance` | d1 来源和 confirmatory/descriptive 资格 |
| `anchors` | 主次生物标签、标签角色和最小 cohort 覆盖 |
| `geometry` | 两种表示的距离、k 和 query/reference 规则 |
| `validation` | 外层留一 cohort、内层 grouped-CV、正则网格和学习曲线 |
| `controls` | label permutation、Null-RP 和 Null-Perm |
| `output` | 覆盖策略、缓存和审计选项 |

### 简化源码职责

可以按四个职责组织代码：

- `R/ablation.R`：公共入口、配置和执行顺序；
- `R/ablation-input.R`：GSClassifier 合同、样本对齐、d1 来源和 manifest；
- `R/ablation-representation.R`：距离、跨 cohort 找近邻、选择性重构和信息损失；
- `R/ablation-statistics.R`：嵌套分组验证、学习曲线和 cohort-level 统计。

如果希望继续保持单文件，也应按这四个职责重排；不需要引入插件系统、新 S4 类或其它复杂抽象。

### 重建结果输出

| 输出 | 保存什么 |
|---|---|
| `manifest.rds` | 样本、两组特征、GSClassifier 合同、module bank、d1 来源、标签角色、fold 和软件版本 |
| `native_geometry.rds` | 距离相关、近邻重合、样本边变化和 module 贡献 |
| `retrieval.rds` | query-to-reference 的逐样本与逐 cohort 生物检索结果 |
| `readout.rds` | nested-LOCO 预测、每折所选参数和两组差值 |
| `learning_curve.rds` | 每个训练规模、重复和测试 cohort 的结果 |
| `tradeoffs.rds` | 按 feature type 的信息保留、独立标签、稀有组和贡献集中度 |
| `audit.csv` | 输入资格、随机索引、指标、差值和 hash 的长表 |

返回对象必须明确写出 `evidence_level = confirmatory/descriptive` 以及降级原因。不再生成 d3、cluster assignments 或 metaCCS parameter-grid 结果。

## 推荐实施顺序

1. 先锁定 Direct-GSClassifier、Cohort-d1、GSClassifier 版本、feature manifest、d1 来源和标签角色。
2. 保留正确输入构建路径，优先修复跨 cohort mixing、query/reference 和 Null 资格问题。
3. 实现两种原生表示的距离、近邻重构和 module 贡献审计。
4. 实现等调参预算的 nested-LOCO 读出与配对学习曲线。
5. 增加按 feature type 的输入保留、独立标签、稀有组和最差 cohort 检查。
6. 最后把下游实验移出默认入口，迁移内嵌测试夹具，并同步 roxygen/Rd、测试说明和 `CHANGELOG.md` 的 `[Unreleased]`；不修改版本号。

## 怎样确认代码改完了

### 科学验收

- 唯一主要差值是 `Cohort-d1 - Direct-GSClassifier`。
- 默认流程不读取 d2、d3、metaCCS、normCCS 或 ICI response。
- 每个收益指标都有对应保护或代价指标。
- confirmatory 结果只接受合格 d1 来源和独立生物标签。
- 学习曲线能区分小样本归纳偏置与信息上限。

### 场景测试

- 确认 GSClassifier 0.4.0 的当前 529 维输入由 32 single-bin、496 gene-pair 和 1 set-pair 组成，并与冻结模型 `dataProc()` 的实际输入列一致。
- 确认 query 只到其它 cohorts 的 reference 中找邻居，跨 cohort 指标不再恒为 0。
- 确认 cohort 内恒定标签会让 Null-Perm 返回 `not_eligible`。
- 确认 `in_sample/unknown` d1 会拒绝或降级 confirmatory 分析。
- 用合成数据验证两种方向：d1 正确去除 cohort 噪声时能够检出收益；d1 过度平滑时能够检出独立标签和稀有组损失。
- 确认两组共享 folds、训练子集、超参数网格和计算预算，但可在训练数据内选择不同最佳参数。
- 改动 held-out cohort 不会改变训练折的标准化、特征过滤或调参结果。
- 相同 seed 可复现，所有随机索引可审计。

### 项目验证命令

- `Rscript test/ablation/test-ablation-config.R`
- `Rscript test/ablation/test-ablation.R`
- 真实数据 representation-only smoke test
- `Rscript -e "devtools::document()"`
- `R CMD build .`
- 使用 `DESCRIPTION` 当前版本对应的 tarball 执行 `R CMD check`
- `python -m bac --root . --bac-file docs/contribution.bac verify --json`

没有项目负责人明确给出目标版本时，不修改 `DESCRIPTION` 版本、tag 或 Release。

## 仍需项目负责人确认的事项

- 是否存在完全外部或严格 out-of-fold 的 d1 评价样本；这是能否形成确认性结论的首要条件。
- 是否有至少一种跨 cohort、样本级变化、未参与 d1 构建的独立生物标签。
- d1 每个 block 是否都是行和为 1 的概率向量；这决定 Hellinger 距离能否作为主距离。
- 旧的 `scaling/tissue_first/metaccs` API 是只取消默认执行、迁移为 legacy，还是在负责人指定的版本中删除。
- 完整 LOCO 学习曲线和 feature-type decoder 的计算预算上限。

## 方法学依据

- CCS 的直接输入合同以本地 GSClassifier 0.4.0 的 `trainDataProc_X()`、`dataProc()` 和冻结模型 feature manifest 为事实来源。经典 TSP 文献只解释其中 gene-pair 组成，不覆盖 single-bin 和 set-pair。
- TSP 的单样本相对表达基础：[Geman et al., 2004](https://doi.org/10.2202/1544-6115.1071)。
- 多研究 TSP 与 cross-study validation：[Kim et al., 2016](https://doi.org/10.1093/bioinformatics/btw115)。
- 普通同研究 CV 可能高估跨研究预测：[Bernau et al., 2014](https://doi.org/10.1093/bioinformatics/btu279)。
- 分子分类器内部验证与独立验证的系统落差：[Castaldi et al., 2011](https://doi.org/10.1093/bib/bbq073)。
- 层级数据应使用 blocked/grouped validation：[Roberts et al., 2017](https://doi.org/10.1111/ecog.02881)。
- 学习曲线要同时考虑训练样本效率和测试不确定性：[Beleites et al., 2013](https://doi.org/10.1016/j.aca.2012.11.007)。
- batch removal 必须与 biological conservation 联合评价：[Luecken et al., 2022](https://doi.org/10.1038/s41592-021-01336-8)；[Büttner et al., 2019](https://doi.org/10.1038/s41592-018-0254-1)。
- d1 来源、折内预处理和嵌套调参必须审计以避免 leakage：[Kapoor and Narayanan, 2023](https://doi.org/10.1016/j.patter.2023.100804)。
