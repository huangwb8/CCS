# 大体积缓存外置与迁移计划

## 当前问题

分析过程中产生的包库、模型和试跑文件与源码一起进入坚果云同步。例如，两个 `renv` 包库合计约 11.2 GiB，`ablation-03/tmp` 约 5.9 GiB；同步这些可恢复的中间文件会挤占云端空间。迁移后，源码和报告仍在项目内，大文件由 D 盘缓存目录托管。

## 改进方向

保留现有正式 targets store 的位置和依赖图，为各分析的包库及临时目录指定外部路径。调整启动入口、隔离测试和历史场景脚本的读写地址，避免下次运行重新生成同步目录中的大文件。`renv.lock`、激活脚本、配置、源码及正式报告继续保留在项目内。

历史 AI 任务中的大型目录整体归档到 `D:/cache/ccs/ai-artifacts/`，原位置保留轻量迁移说明。无需目录链接；坚果云是否跟随链接不再影响缓存隔离。

## 实施顺序

1. 清点文件体积、现有未提交修改和分析进程，确定迁移清单；不接触正在使用的正式 store。
2. 静态调整路径，更新 AGENTS.md、相关运行说明及 CHANGELOG 的 Unreleased 条目。
3. 将清单中的文件复制到外部目录，逐文件核对 SHA-256、大小及数量，全部通过后才移除原件。目标已存在且内容不同时停止，不覆盖。
4. 仅做 R/PowerShell/Python 语法检查、路径引用检查和 BAC 哈希链验证，不启动分析、训练、报告渲染或 targets。

## 验收与恢复

迁移清单记录源路径、目标路径、字节数和哈希。原目录不保留通向外部缓存的 junction 或符号链接。现有正式 targets store 与 observability 目录不变，科学计算参数和包版本不变。若复制或校验失败，保留源文件；已校验迁移的数据可依据清单复制回原位置。

历史试跑缓存可能序列化了旧绝对路径，迁移不承诺其可直接恢复执行；需要再次执行时仍通过相应正式 targets 入口，由其判断依赖是否失效。本次不修改序列化结果，也不重算它们。

## 继续外置生成结果

根据负责人的补充要求，正式报告及批量结果也改为默认外置。将 normCCS-premium、ablation-03-max 和 ablation-03 的生成 HTML、表格、图形及配套快照放入各自 cache root 的 `exports/`。源码、Rmd 模板、配置、Markdown 草稿及必要的小型输入素材继续保留。

先统一生产端与消费端的输出配置，尤其检查论文组图读取的导出表、图形合成素材和隔离验收脚本；再复制、逐文件核对哈希并移除原件。README 与当前说明中的结果链接指向新位置，Git 忽略规则防止本地旧目录中的生成结果再次进入提交。正式 store 及现有元数据保持不变，本次仍不运行分析或渲染报告；后续由原 targets 图判断迁移后文件依赖是否失效。
