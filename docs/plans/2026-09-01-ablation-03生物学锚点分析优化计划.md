# ablation-03 生物学锚点分析优化计划

## 通俗解释：究竟发生了什么

现在的 ablation-03 已经有一套“坐标系比较”：Direct-GSClassifier 和 Cohort-d1 对同一样本找出的邻居不同，d1 也减少了部分癌种和技术来源聚集。但这还像只检查地图的道路形状，没有检查地图上真正重要的地点是否仍然标对。

生物学 anchor 就是独立的“参考答案”：增殖分数、免疫/基质状态、通路活性、PAM50 或 CRC CMS 等。完整表达矩阵提供样本的原始表达，signature 提供要寻找的生物状态，Direct/d1 提供两套表示。改进后的分析要在同一批外部 query 上计算这些参考状态，再比较哪套表示更能在未见 cohort 中读出它们。

例如，同一个样本在 Direct 和 d1 下各自取 15 个邻居：现在只看邻居是否同癌种；改进后还要看邻居的增殖、免疫和基质分数是否相近。如果 d1 降低技术来源聚集，同时这些独立生物分数没有下降，才支持“选择性重表达”；如果所有生物分数一起变差，只能报告为平滑或信息损失。

## 专业判断：问题在哪里

### 当前事实

- 完整矩阵和已整理 signature 均存在，数据规模足以覆盖 03 的 query/reference 对齐与生物学评分。
- `GeneSignature-HWB.rds` 已提供增殖、Immune/TME、基质、IFN/IL6、TLS、免疫调节等候选 signature；它是当前最直接的外部连续 anchor 来源。
- `E:\iProjects\candidateR\BI_immune_deconv.R` 已提供 `immune_deconv()`，可调用 MCP-counter、xCell、EPIC、ESTIMATE、ConsensusTME 等多种免疫/微环境估计方法。
- `E:\iProjects\candidateR\BI_signature_ssGSEA.R` 已提供 `signature_ssGSEA()`；`E:\iProjects\candidateR\TMEscore.R` 已提供 `sigScore()` 和 `tmescore()`。
- `E:\RCloud\RFactory\lucky\R\BI_FastMS.R` 的 `FastMS()` 能读取本地 MSigDB gene set，适合 GSEA/富集解释；它不是逐样本 anchor score 函数，不能直接替代 ssGSEA/GSVA。
- 当前 `test/ablation-03/03-ablation-biology.R` 只实现少量 signature 的均值评分，尚未纳入 immune deconvolution、ssGSEA/GSVA、FastMS、PAM50/CMS，也没有完整的 anchor-level cross-fitted readout。
- 本地尚未核对到可直接冻结使用的 PAM50/CMS gene list 或分类器；这不是表达数据不足，而是参考分类器的出处和版本尚未固化。

### 现有候选函数的接入边界

- `immune_deconv()` 适合生成免疫细胞/TME abundance 的连续外部 anchor，但不同方法对表达尺度和输入类型有要求，不能把所有方法的数值直接混在一起；应保留方法名、输入尺度、失败状态和版本。
- `signature_ssGSEA()` 适合按样本计算 pathway/signature activity；当前实现的全局 min-max 归一化会受样本集合影响，主分析应保存原始分数，并把归一化限定为展示或预先冻结的 cohort 内变换。
- `sigScore()` 的 PCA 与均值方式适合对小型发表 signature 做敏感性比较；PCA 方向必须固定，不能在不同 arm 中任意翻转。
- `tmescore()` 可作为 TMEscoreA/B 的既有实现，但默认 PCA、自动 log2 和生存二分类功能必须在本任务中显式锁定；本轮不调用其 survival cutoff 功能。
- candidateR 代码应优先复用，但项目入口的包加载仍遵守 `luckyBase::Plus.library()`；不在 `.Rmd` 中直接 `library()`。若发现 candidateR 中的兼容性问题，优先在 03 的 wrapper/helper 中做最小适配，不覆盖原始候选脚本。

## 要达到什么目标

### 完成后的变化

1. 建立一个冻结、可追溯的 biological-anchor manifest，记录来源、版本、ID 类型、基因列表哈希、CCS/Direct 重叠、适用 tissue/cohort 和最低覆盖率。
2. 在完整表达矩阵中按 `sample_id + cohort` 对齐 03 的 reference/query，只缓存目标样本的 anchor score，不复制 5 GB 级原始矩阵。
3. 形成“连续 anchor + 免疫去卷积 + 经典亚型分类 + GSEA 机制解释”的分层证据链。
4. 在相同外部 query、相同 cohort 留出和相同 readout 容量下比较 Direct-full、blocked Direct、PCA/RP、公平压缩对照、d1-full 和 own-block-masked/OOF d1。
5. 输出 cohort-level/tissue-level 的效应量、95% CI、最差 cohort、覆盖率、`not_estimable` 状态和多重比较校正，而不是只给一个总体均值。

### 不在本次处理范围

- 不把 GSEA 的显著通路直接当成 d1 优越性的证据；GSEA 只解释预先定义比较下的表达差异。
- 不从 CCS pseudo-subtype 反推 PAM50/CMS，不使用未记录出处的网络 gene list。
- 不把 cancer type 当作 biological utility；它继续作为 lineage recoverability 诊断。
- 不把候选方法全部无差别跑一遍后按最好结果挑选；主分析方法和敏感性方法必须在看结果前冻结。
- 不复制或修改完整表达矩阵、GeneSignature RDS、candidateR 原始脚本和冻结模型；不覆盖 ablation-02 结果。
- 不在本阶段扩展到生存、治疗反应或 d2/d3/metaCCS 的完整临床验证。

## 改进方向

### 冻结数据、样本键和 anchor manifest

以 `E:\Sync\@Analysis\PanCan_Data\Level 1\PanCan_CancerSample_DataListForCCS_GEO+cBioPortal+UCXCXenav20240809.rds` 为表达主输入，以 `test/ablation-03/tmp/ablation-experiment/manifest.rds`、`retrieval.rds` 和 `data-profile.rds` 为 03 的样本边界。完整矩阵按 tissue/cohort 分块读取；每个样本使用 `sample_id + cohort_id`，全局重复 ID 进入重复键审计，不静默覆盖。

manifest 分三层：

- **主连续 anchor：**`GeneSignature-HWB.rds` 中的 Tumor proliferation rate、TME_A_Immune2、TME_B_Stromal2、IFN signaling、IL6-JAK-STAT3、TLS/免疫调节候选。
- **免疫/TME 正交 anchor：**通过 `immune_deconv()` 预先指定 MCP-counter 为主方法，xCell 或 ESTIMATE/ConsensusTME 为敏感性方法；方法失败或输入尺度不合适时记录状态，不用另一方法悄悄替代。
- **分类 anchor：**BRCA PAM50 和 CRC CMS。先找到带论文出处、版本和冻结基因列表/分类器的本地资源；若找不到，建立外部来源 manifest 后再运行，不临时从现有结果反推标签。

每个 signature 同时记录 SYMBOL/ENSEMBL、原始基因数、矩阵命中数、cohort-level coverage、CCS 32 基因重叠、Direct gene-pair 重叠、disjoint 版本和适用 tissue。主结论优先使用 disjoint 版本；full-signature 作为敏感性分析。

这一步对研究者意味着：以后任何结果都能回答“这个 anchor 来自哪里、覆盖了哪些样本、是否与 CCS 输入重叠”，不会把数据缺失或循环输入误认为生物学发现。

### 建立统一的表达预处理和评分层

在 `test/ablation-03/03-ablation-biology_functions.R`（必要时新增）中实现统一 wrapper，候选函数只作为底层实现：

- 用 `luckyBase::convert()` 完成 ENSEMBL/SYMBOL 转换，并保留原始 ID、转换统计和重复聚合记录。
- 对每个 cohort 单独执行必要的表达变换/标准化；保存 raw score、cohort-standardized score 和用于展示的 bounded score，禁止用全体样本的 min-max 影响外部 query。
- 用 `signature_ssGSEA()` 计算预先冻结的 pathway/signature 分数；用 `sigScore(method = "PCA")` 与均值方式做指定敏感性比较；PCA 方向按与 signature gene mean 的相关性固定。
- 用 `immune_deconv()` 运行主方法和敏感性方法，输出每个方法的 cell-type matrix、输入尺度、软件版本、成功/失败状态、缺失原因和样本覆盖率。
- 对小于最低基因覆盖率的 anchor 返回 `not_estimable`，不通过补零或临时替代 signature 强行评分。

大矩阵只做一次按 cohort 的读取和目标样本抽取；cache key 至少包含表达文件 md5、sample-key hash、anchor manifest hash、预处理参数和软件版本。cache 不匹配时重新计算或明确失败。

### 设计分层的生物学效用 readout

#### 连续状态

对增殖、免疫、基质、IFN/IL6、免疫细胞 abundance 等连续 anchor，比较 Direct/d1 top-k 邻居的：

- 邻居内平均绝对 score 差；
- Spearman/Kendall 排序一致性；
- `exp(-abs_delta)` 等 bounded utility，仅作为辅助展示，不替代原始误差；
- query-cohort macro 汇总、最差 cohort、cohort-bootstrap 95% CI；
- anchor 间相关性和方法间一致性，避免把同一生物轴的多个高度相关 signature 当作独立证据。

#### 分类状态

对 PAM50/CMS 使用 leave-one-cohort-out readout，至少报告 macro-AUROC、balanced accuracy、类别覆盖、混淆矩阵和 `not_estimable` cohort。分类器/centroid 只在 reference cohort 训练或冻结，在外部 query 上评分；不根据 d1 结果重新挑选基因或类别。

#### 免疫去卷积

将去卷积结果视为连续外部 anchor，不把不同算法的细胞比例直接相加。主分析使用一个预先指定方法，第二方法只用于方向一致性敏感性；报告方法间相关、失败率和 platform/source 分层结果。

### 正确使用 GSEA 与 MSigDB

`lucky::FastMS()`（实现：`E:\RCloud\RFactory\lucky\R\BI_FastMS.R`；gene set：`E:\RCloud\RFactory\lucky\inst\extdata\msigdf.human.7.1.rds`）用于组间或排序列表解释：

- 以外部 anchor 高低组、预先定义的邻域一致/不一致组，或 Direct/d1 读出差异对应的表达排序作为输入；
- 预先锁定 MSigDB 版本和类别（建议 H、C2、C5 中与研究问题相关的子集），保存输入 geneList、背景基因、参数和结果；
- 报告 NES、p 值、FDR 和 leading-edge，解释哪些通路与 anchor 变化相符；
- 不把 d1 的 module 列名直接伪装成 gene-level GSEA 输入，也不把 GSEA 的 q 值当作 sample-level utility。

这一步的目标是解释“哪些生物过程与表示差异相连”，而不是用通路数量制造 d1 胜出结论。

### 引入公平对照、交叉拟合和独立性检查

每个主要 anchor 共享同一批 query 和 cohort split，比较至少包括 Direct-full、blocked Direct、PCA/rank grid、multi-seed random projection、d1-full、d1-own-block-masked；预算允许时加入 d1-own-block-OOF。readout 模型、调参预算、类别权重和 bootstrap 统计单位保持一致。

主分析前完成以下独立性审计：

- 排除或单独报告 CCS 32 genes 与 Direct gene-pair 重叠；
- anchor 不参与 bank selection、rank selection、方法选择或终点选择；
- reference own-cohort block 屏蔽，避免 in-sample fingerprint；
- 以 cohort/design repeat 为统计单位，不把同一 query 的多个邻居当作独立实验重复；
- 多 anchor、多方法和多 endpoint 使用预先定义的层级与 FDR 控制。

### 将结果接入 03 报告而非散落在脚本中

`.R` 层负责全量计算和缓存：alignment audit、signature score、deconvolution、GSEA 输入/结果、readout 和 inference。`.Rmd` 层负责阈值筛选、图表、指标导读和解释；不在 Rmd 内重复读取 5 GB 矩阵或重新计算分数。

报告新增章节建议为：数据与 anchor 覆盖、连续 anchor、免疫/TME 去卷积、PAM50/CMS、GSEA 机制解释、联合 selective-invariance 判断、限制与后续。每个表/图附近都写绑定当前数字的解读；不常用指标首次出现时说明尺度、参考点、方向和不确定性。

图表输出遵守矢量 PDF + JPG 预览；关键参数集中在 Rmd 参数区块，HTML 使用 PDF 渲染出的 JPG，逐图检查长 cohort 标签、图例、字体和比例。

## 实施范围与顺序

1. **资源与键审计：**读取完整矩阵、GeneSignature-HWB、03 manifest/retrieval/data-profile，建立 anchor manifest、ID 转换和 coverage audit；先确认 sample/cohort 对齐，再确定可运行的 PAM50/CMS 来源。

4. **分类与通路解释：**冻结 PAM50/CMS 后加入 BRCA/CRC leave-one-cohort-out；对预先定义的 anchor 高低或 readout 差异执行 FastMS GSEA，保留 NES/FDR/leading-edge 和背景说明。
5. **联合推断与边际贡献：**将 biological utility、technical excess、worst-cohort、label-efficiency 和 effective rank 放入同一判读矩阵；在固定 base bank 下做 paired marginal cohort addition，报告新增 cohort 带来的生物学收益与技术代价。
6. **报告与质量门禁：**更新 03 Rmd/README/config，运行原有 02 兼容测试和 03 新增合同测试；渲染 HTML，执行图表/表格解读覆盖、HTML widget 可见性、包文档/构建检查和 BAC verify。

## 风险与待确认事项

- **R 运行环境：**当前执行机曾缺少 `Rscript`；正式计算必须在安装 CCS、luckyBase、GSVA/immunedeconv 及其依赖的 R 环境中进行。缺少 R 时只能完成静态审计，不能把计划标记为结果已验证。
- **完整矩阵内存：**5 GB 级 gzip-RDS 不应被多个脚本重复加载；优先单进程分块抽取并保存 score cache，必要时由项目负责人提供足够内存环境。
- **表达尺度：**immune deconvolution、GSVA/ssGSEA 和简单 z-score 对输入尺度要求不同；每个方法必须记录变换，禁止把不同尺度的结果直接比较。
- **候选函数兼容性：**`BI_immune_deconv.R`、`BI_signature_ssGSEA.R`、`TMEscore.R` 是已有候选代码，接入前需验证包 API、空矩阵、重复基因和缺失值边界；优先在 wrapper 中适配，避免未经授权改动外部脚本。
- **基因 ID 与重叠：**完整矩阵可能以 ENSEMBL 为主，signature 同时存在 SYMBOL/ENSEMBL；统一使用 `luckyBase::convert()`，并保留转换审计。与 CCS/Direct 输入重叠的 anchor 必须有 disjoint 敏感性版本。
- **PAM50/CMS 来源：**目前未发现本地冻结资源；需先锁定发表版本和适用 cohort，不能用 cancer type 或 CCS pseudo-subtype 代替。
- **多方法多终点：**signature 扫描和多种去卷积会放大多重比较；主 anchor、敏感性 anchor 和 exploratory FastMS 必须分层报告并控制 FDR。
- **解释边界：**生物 anchor 不下降不等于 d1 已发现新状态；只有在外部 cohort 稳定、技术 excess 不升高、最差 cohort 不恶化的组合证据下，才可支持 selective-invariance。
