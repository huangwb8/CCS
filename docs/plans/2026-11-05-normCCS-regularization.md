# normCCS 快速搜索正则化实施计划

训练 AUC 接近的两个映射，可能具有很不一样的样本支持：其中一个等级只有几条记录，另一个则有较充分的数据。当前 `stream_exact` 主要按 AUC 目标选择；本次让稀疏等级承担额外代价，降低搜索追逐小样本波动的倾向。

## 改进范围

仅扩展离散 `stream_exact`。新增 `norm_min_grade_n = 1L` 和 `norm_regularization = 0`，分别控制每级合并训练记录数底线和软惩罚强度。关闭时保留原结果。公共入口追加参数，其他后端对非默认设置明确报错，避免静默忽略。

固定 K 时，选择得分为原 AUC 汇总目标减去 `lambda * mean(1 / sqrt(n_g))`。人数来自合并训练记录，仅计一次，不把 pooled All 与各队列重复相加。惩罚不要求各级同时出现两类结局。它偏向人数较均衡的分组，可能压制真实稀有亚群，并非统计置信下界。强度须由训练侧分组验证确定。

## 实施顺序

1. 将人数约束和惩罚加入原 C++ 全空间遍历与 Top N 堆，在 R 中独立核对。保留原 AUC，另外返回选择得分、惩罚和每级人数。
2. 在 `tmp/normCCS-regularization-089/` 编写合成验证，覆盖穷举、Top N、无合法解、边界、多线程、公共入口和零惩罚回归。编译、模型、结果及日志外置到 `D:/cache/ccs/normCCS-regularization-089/`。
3. 用无信号、稀疏状态和稀有真实信号的独立训练／测试模拟检查行为，并比较运行开销。模拟结果只解释适用边界，不代替真实队列的分组验证。
4. 同步双语 README、接口文档和 CHANGELOG。完成开发验证后，按负责人授权更新至 0.8.9，以 R 4.3.1 构建、检查、安装并核对本机版本。

## 验收与解释边界

候选必须是给定排序、K、人数约束及正则化目标下的精确 Top N，允许合法候选少于请求数；无合法解明确报错。零惩罚和默认底线须复现 0.8.8；原始 AUC 不得被惩罚覆盖。串并行结果一致，C++ 与独立 R 穷举一致。

本次不改变应答排序、Raw 自动方向或 OptimizeRank 语义，不运行或替换既有真实分析。正则化不能消除标签泄漏，也不保证每个数据集的外部 AUC 上升。测试及交付报告按 humanization 技能复核表达与事实边界。

## 执行结果

已完成开发、1936 项断言、合成模拟、速度基准、0.8.9 构建检查和本机安装核对。模拟确认了稀疏等级支持的改善，也显示了对稀有信号的损失；默认关闭保持不变。方法、数值结果和复现入口见[开发与验证报告](../normCCS-regularization.md)。
