# normCCS 论文口径恢复计划

## 问题与目标

本轮重新搜索时换了训练队列和状态排序，导致四级方案不再对应论文中的比较条件。应先恢复论文原有的数据与计算口径，再比较不同等级数。论文固定四级映射必须单独保留，避免把新搜出的四级映射当作已有方法。

源代码与论文目录均只读。修改范围限于本项目的分析函数、targets 依赖图、配置、验证与说明；不调整包 API、版本或上游模型。

## 恢复依据

以用户提供的原始 normalization 与选定模型脚本、对应缓存为依据，核对实际 20 个推导队列、1177 条记录、二分类应答、原状态集合、NRR 的计算与并列排序、连续切分、OptimizeRank 和训练队列中位数目标。不能只复用参数名称而改变其输入数据。

只读核对进一步发现：原 K=2 保存结果包含 107 个状态，当前重建输入重算则为 108 个状态，部分顺序也不同。因此最终实现直接恢复原 K=2 表中完整、逐候选一致的历史状态顺序，不能复用此前 `paper_` 分支重算的顺序。K=2–4 分别枚举 106、5565、192920 个连续切分，并检查原四级映射被实际枚举回收。原 K=4 保存表也已独立确认包含该映射，训练中位数为 0.7296650717703349。

原代码的数据作用域与现有文字描述不一致时，应记录具体调用链和缓存证据，不自行解释为使用外部数据选择映射，也不擅自改变数据范围。无法确认某一口径时暂停依赖该口径的正式计算，明确未决项。

## 实施顺序

1. 建立原始训练名单、逐队列记录数、样本／结局／CCS 和排序的一致性检查，先确认复现输入。
2. 在现有 `_targets.R` 增加论文对齐分支，保留旧隔离分支及产物，使用同一正式 store；新产物使用独立科学缓存命名空间。
3. 正式导出论文固定映射基线，同时标明原公共队列 OptimizeRank AUC 与固定等级 AUC。新候选与原基线分开标识，不按外部成绩挑选候选。
4. 经同 DAG 小输入测试后，通过正式 targets 入口执行、验证与恢复检查，再同步 README、结果说明和 CHANGELOG。

## 完成标准

训练队列、实际记录和排序均有参考一致性证据；K=2–4 的穷举范围明确，低 K 计数内核与原 ROC 计算等价，并与 DP 核对相同映射；论文组合在 K=4 候选中存在；论文基线复现既有 AUC，外部原始 CCS 不变；训练评分和外部评价的口径分别列出。正式结果只能由 targets 产生，验证未通过不得宣称已经恢复论文口径。

## 扩展至 K=30

负责人指定探索上限为 30，约为 107 个历史状态的三分之一。本轮补齐 K=13–30，继续使用原 20 个训练队列、107 状态顺序、训练队列 OptimizeRank AUC 中位数和既有 DP 内核；不改变训练资格、评分定义或论文四级基线，不增加其它 K 范围。

先保存 K=2–12 的聚合结果作为一致性参照，再更新配置与动态范围验收。合成输入覆盖 K=13、20、30 的搜索和评价，核对同一 DAG、训练评分复算、每级人数和恢复复用；正式结果仍通过 `aligned_acceptance` 生成。扩展后逐项比较原 K=2–12 的映射、训练分数及外部 AUC，保证增加探索范围没有改变已有科学结果。报告同时展示每级患者支持，避免仅按原状态压缩比例解释高 K。
