# ablation-03 表达矩阵缓存与分层处理优化计划

## 通俗解释：究竟要解决什么

现在的 biology 脚本把“读取 5 GB 原始表达矩阵”和“计算 biological anchor”放在同一次运行里。这样每次改一个分析参数，都可能重新触发一次高峰内存占用；一旦读取失败，anchor 结果只能记为 `not_estimable`。

本计划把工作拆成两次：第一次只负责读取原始矩阵、提取本轮预先冻结的 signature 基因并保存小缓存；以后每次分析只读取这个缓存。这样大矩阵只承担一次性准备工作，分析阶段可以反复运行、调试和复核。

## 专业判断：当前问题在哪里

- 原始表达矩阵文件约 5.23 GB，`readRDS()` 解压并构造对象时的峰值内存会高于文件大小；后续 `as.matrix()`、筛选和转换还可能产生额外副本。
- 当前 [03-ablation-biology.R](../../test/ablation-03/03-ablation-biology.R) 在读取完整矩阵后才筛选样本和基因，读取失败时只能整体退出。
- 当前 [03-ablation-biology.py](../../test/ablation-03/03-ablation-biology.py) 虽然能捕获 `MemoryError`，但同样把完整 RDS 作为分析阶段输入，不能避免重复高内存读取。
- signature 选择已经写入 [biological-anchors.yml](../../test/ablation-03/config/biological-anchors.yml)，应进一步把“所需基因并集、ID 类型、与 CCS 输入重叠处理”冻结到缓存清单中。

## 目标

- 将原始矩阵读取、signature 基因规划、子集提取和缓存写入从 biology readout 中分离。
- 后续 R/Python 分析只加载缓存，不再默认读取完整表达矩阵。
- 缓存可判断是否过期，避免使用与当前 signature、样本集合或预处理不匹配的旧结果。
- 在不改变 ablation-02 结果和 Direct/d1 比较口径的前提下，恢复 ablation-03 的独立 biological anchor readout。

## 非目标

- 不修改原始表达矩阵、GeneSignature-HWB.rds 或 ablation-02 的结果。
- 不在本轮改变 anchor 的科学定义，不进行事后挑选最优 signature。
- 不把缓存成功等同于生物学结论成立；最终仍需跨 cohort 的独立 readout。
- 不扩展到 d2/d3/metaCCS、临床结局或治疗反应验证。

## 改进方向

### 冻结 signature 与缓存契约

以 `biological-anchors.yml` 为入口，读取本轮所有主分析 anchor 的基因并集，至少覆盖增殖、immune/TME、stromal/TME 和 IFN/IL6。缓存清单记录每个 anchor 的来源、版本、原始基因数、实际命中基因数、ID 类型和 CCS 输入重叠情况。

缓存对象建议至少包含：

- 按 tissue/cohort 保存的子集表达矩阵；
- `required_genes` 及每个 anchor 的基因列表；
- `sample_id`、tissue、cohort 对齐信息；
- 原始 RDS 哈希、signature manifest 哈希和预处理参数；
- 生成时间、脚本版本和缓存 schema 版本。

只要源文件哈希、signature 哈希、样本键或预处理参数不匹配，分析脚本就拒绝静默复用旧缓存，并返回明确的 stale/mismatch 原因。

### 新增独立的数据处理阶段

新增 `test/ablation-03/01-ablation03-biology-cache.R`，职责仅限于：

1. 读取并校验原始表达矩阵与 signature RDS；
2. 根据冻结 manifest 计算所需基因并集；
3. 按 tissue/cohort 提取所需基因和可匹配样本；
4. 记录缺失基因、重复 sample key、cohort 覆盖率和 ID 转换审计；
5. 将结果写入 `test/ablation-03/tmp/ablation-biology/expression-anchor-cache.rds`；
6. 保存成功后执行 `rm()` 和 `gc()`，释放完整矩阵及循环中的临时对象。

实现时避免对每个 cohort 先 `as.matrix()` 再复制完整对象；应尽量先按行列索引取子集，再进行必要的数值转换。缓存压缩方式以体积、读取速度和当前环境可用性为准，默认优先可重复读取的 gzip，并记录压缩参数。

### 将 biology readout 改为缓存消费者

修改 [03-ablation-biology.R](../../test/ablation-03/03-ablation-biology.R)：

- 默认读取 expression-anchor-cache，而不是完整表达矩阵；
- 校验 cache schema、source/signature/sample hash；
- 仅在缓存不存在或不匹配时给出可操作错误，不自动回退到完整矩阵读取；
- 保留现有 coverage、z-score signature mean、utility 和 Direct/d1 paired contrast 的定义；
- 对单个 anchor 或单个 cohort 的缺失继续使用 `not_estimable`，不补零、不借用其它 cohort。

同步调整 [03-ablation-biology.py](../../test/ablation-03/03-ablation-biology.py)，使 Python fallback 消费同一缓存契约，避免 R 与 Python 两套输入逻辑产生不同结果。

### 保持分析与展示分离

缓存脚本负责全量计算和审计；biology 分析脚本负责 readout；`02-ablation03-experiment.Rmd` 只读取 CSV/RDS 结果并展示，不重新加载大矩阵。这样修改图表或文字时不会触发表达矩阵读取。

## 实施顺序

1. 冻结并审查 YAML 中的 anchor、gene ID 类型、CCS 输入重叠规则和缓存 schema。
2. 新增缓存构建脚本，完成源文件/签名/样本键哈希及 coverage 审计。
3. 修改 R biology readout，使其只消费缓存并明确处理过期、缺失和不匹配状态。
4. 修改 Python fallback，使其读取同一缓存格式；若缓存不存在，安全停止并报告原因。
5. 增加小型 fixture 测试，验证基因子集、重复键、缺失基因、缓存命中和缓存失效行为。
6. 在有足够内存的 R 环境中先构建缓存，再运行 biology readout 和 HTML 报告。
7. 复核 anchor coverage、utility、contrast 是否有有效行，并确认 `not_estimable` 只对应真实不可估计单元。
8. 运行项目测试、包检查和 BAC 验证；确认 ablation-02 文件未被写入或覆盖。

## 验收标准

- 原始表达矩阵只在缓存构建阶段读取一次；后续分析日志中不再出现完整矩阵读取。
- 缓存中只包含预先冻结 anchor 所需基因及目标样本，且可通过 manifest 追溯来源。
- 缓存构建完成后释放大对象；分析阶段不再因重复加载完整矩阵触发 `MemoryError`。
- 至少三个预先定义的独立 anchor 产生有效 coverage 和 utility 结果；无法估计的 cohort 有明确原因。
- Direct/d1 使用相同 query、reference 和 top-k 邻居，结果 schema 与现有报告兼容。
- 缓存失效、基因缺失、ID 重复和输入重叠均有可读错误或审计记录。
- 既有 ablation-02 结果、模型文件和版本号不变；`R CMD check`、相关场景测试和 BAC verify 通过。

## 风险与待确认事项

- **一次性建缓存仍需要足够内存**：缓存方案降低重复分析成本，但不能消除首次 `readRDS()` 的内存要求；必要时需在更大内存环境运行，或进一步按文件内部结构分块读取。
- **表达矩阵与 signature 的 ID 类型可能不一致**：必须保留 SYMBOL/ENSEMBL 转换审计，不能把未匹配基因静默当作缺失无害。
- **ssGSEA/TME 方法可能需要额外背景基因**：正式冻结前需确认每种评分方法的最小输入范围，不能只保存表面上列出的 anchor 基因。
- **缓存过期风险**：source hash、manifest hash、sample-key hash 和预处理参数必须参与 cache key。
- **内存释放不是绝对保证**：`rm()`/`gc()` 只能回收 R 已不再引用的对象；应避免隐藏引用和不必要的矩阵复制。

## 最终检查

- 计划只涉及 ablation-03 的数据处理与 biology readout，不改变项目版本号。
- 正式实施前需要先确认 anchor 基因并集和 ID 转换规则；确认后再运行一次性缓存构建。
- 本计划获确认后再修改脚本；当前不执行大矩阵读取、不生成新的科学结论。
