# ablation-03 生物学锚点与 d1 表示性质优化计划

## 通俗解释：02 已经说明了什么，03 要补上什么

- **一句话说明：**02 已经证明 d1 和 Direct-GSClassifier 的“坐标系”明显不同，但还没有证明这个新坐标系是否更能表达增殖、免疫微环境或疾病内部亚型等生物状态。
- **具体场景：**可以把 Direct 看成按原始基因特征整理的一本账，d1 则是许多 cohort 专家把同一批样本重新打分后拼成的“证据账本”。02 已经发现两本账的邻域和癌种可读性不同；03 要拿一套事先冻结、独立于 CCS 训练的生物学参考答案，检查两本账对同一个生物状态的表达是否一致。
- **数据对应关系：**02 的 38,841 个唯一样本 ID 在补充的完整表达矩阵中全部能找到；完整矩阵提供每个样本的宽基因表达，`GeneSignature-HWB.rds` 提供已整理的发表过的细胞周期、免疫/TME、IFN/IL6、TLS 和免疫细胞等签名。02 的样本、队列划分和技术元数据继续作为主比较边界。
- **改变前后：**现在只能说“d1 改写了表示、降低了癌种/技术来源的局部可恢复性”；03 完成后，至少可以进一步说“这种改写是否在独立生物锚点上保持或改善跨 cohort 的可读性”，并能区分生物学重表达、普通压缩和无选择的信息损失。

## 专业判断：问题在哪里

### 当前事实

- 02 的主结果来自 529 维 Direct 与 583 列 d1 的比较，已覆盖 24,487 个 reference 样本、10,103 个 query 样本、147/36 个 reference/query cohort，并已完成几何、retrieval、readout、decoder、技术来源和 breadth/depth 等审计。
- 02 目前的独立 anchor 主要是 `cancer_type`。它适合作为 lineage recoverability 诊断，但不能代表增殖、免疫/TME、分子亚型或其它生物状态。
- 完整矩阵包含 45,558 个样本行、45,286 个唯一样本 ID、约 37 个 tissue 和 292 个 cohort；其中 02 的 38,841 个唯一样本全部匹配。新增 cohort 不一定有与 02 工作簿同等完整的平台/来源元数据，因此不能未经审计就并入技术因果比较。
- `GeneSignature-HWB.rds` 可展开为 120 个 signature 叶节点。签名同时使用 SYMBOL 与 ENSG；PAD/PIAM、PAD/PIDG 与 CCS 当前 32 个输入基因重合，不能作为主 anchor，否则会把 CCS 输入重新当作独立证据。

### 需要避免的误读

- biological anchor 表现不下降，只能说明生物状态表征没有明显受损；只有在预先定义的效应、技术泄漏下降和跨 cohort 稳定性同时满足时，才可以称为选择性不变性。
- d1 的列数多于 Direct，不能称为字面意义上的降维；应使用 structured re-encoding、有效秩和 utility–complexity 曲线描述。
- anchor、rank、bank 组成和成功阈值必须在查看结果前冻结；anchor 不参与 bank selection、模型调参或最佳结果筛选。

## 要达到什么目标

### 完成后的变化

1. 在不覆盖 `ablation-02` 的前提下，先把 `test/ablation-02/` 的分析源代码、模板和测试结构复制为 `test/ablation-03/`，让 03 自己运行并包含 02 的全部分析；然后只在 03 副本中增加生物学 anchor、干净 provenance、公平压缩对照和机制对照。

3. 给出联合判断：生物学表现、技术来源泄漏、最差 cohort 表现和低标签量表现是否形成支持性组合；若只观察到技术信息下降而生物 anchor 同时下降，明确解释为 trade-off 或 indiscriminate smoothing。

## 改进方向

### 建立完整矩阵与 02 样本的可追溯对齐层

在 `ablation-03` 的数据入口中，以 `sample_id + cohort_id` 作为主键，把 02 的 reference/query 分区映射到完整表达矩阵；全局重复 sample ID 不按 sample ID 单列去重。保存以下审计字段：源文件哈希、匹配样本数、未匹配样本数、重复键、tissue/cohort 映射、每个 cohort 的基因数和表达矩阵方向。

主分析先使用与 02 完全相同的 39,112 个样本行，保证 Direct/d1 差异可直接比较；完整矩阵的额外样本和 cohort 作为扩展层，只有通过样本身份和签名覆盖检查后才参与 biology-only 分析。

这一步对研究者意味着：03 的生物学结果可以明确回答“是不是同一批 02 样本上的新证据”，不会因为换了数据版本而把数据变化误当作 d1 效应。

### 建立冻结的 biological-anchor 目录

先对 `GeneSignature-HWB.rds` 做一次只读清点和 ID 统一：

- 将 SYMBOL/ENSEMBL 统一到完整矩阵实际使用的 ID；记录转换方法、重复基因和每个 cohort 的可用比例。
- 主 anchor 预先选择少量互补类别，而不是把 120 个签名全部当作同等主要终点。优先包括：cell-cycle/proliferation、immune/TME、IFN/IL6 或 immunomodulator、TLS/免疫细胞状态。
- PAD/PIAM、PAD/PIDG 以及与 CCS 32 个输入基因高度重叠的签名排除出主结果；对其余签名报告 CCS-input-disjoint 的敏感性版本。
- PAM50 与 CRC CMS 使用已发表的冻结基因列表或本地已有实现；如果本地没有可审计版本，先建立带来源、版本和基因列表哈希的最小 anchor manifest，再进入正式评分。不能用 CCS pseudo-subtype 代替 PAM50/CMS。
- 对 120 个签名中未进入主分析的部分保留 exploratory 扫描，统一进行 FDR 控制，不把事后挑出的单个显著签名写成主要结论。

每个 anchor 都需要记录签名来源、方向、所需基因、实际覆盖率、是否 disjoint、适用 tissue/cohort 和是否允许用于分类 readout。anchor manifest 在所有模型选择之前冻结。

这一步对研究者意味着：生物学“参考答案”来自独立发表的基因集合，而不是 d1 自己制造的标签，能真正检验 d1 是否表达了新的有意义状态。

### 设计 cross-fitted biological readout

在同一 query cohort 上，对每个 anchor 分两类评估：

- **连续状态：**以外部 signature score 为目标，计算跨 cohort 的 Spearman、MAE/RMSE 或 rank-based concordance，并报告最差 cohort 和 cohort-macro 汇总。
- **分类状态：**对 PAM50、CMS 或其它有明确类别定义的 anchor，使用 leave-one-cohort-out 的 macro-AUROC、balanced accuracy 和类别覆盖审计；类别不足的 cohort 标记为 `not_estimable`，不强行合并。

比较 arms 至少包括：

- Direct-full；
- Direct-blocked/module-balanced；
- PCA(Direct) rank grid；
- RandomProjection(Direct) 多 seed；
- d1-full；
- d1-own-block-masked；
- d1-own-block-OOF（计算预算允许时）。

所有 arms 使用相同样本、相同 query cohort、相同 readout 模型容量和相同调参预算。reference 的 own-cohort d1 block 必须先屏蔽；决定性版本使用 K-fold OOF 预测。biology anchor 不参与 d1 训练，也不参与模型选择。

这一步对研究者意味着：如果 d1 的技术来源信息下降，但增殖/免疫/TME 等生物状态仍能跨队列读出，才有资格说它可能是“选择性重表达”；如果所有 anchor 都一起下降，就只能报告信息损失或权衡。

### 将 02 的机制审计纳入 03 主报告

03 报告直接运行复制后的 02 分析代码，独立生成几何、retrieval、readout、decoder、learning curve、technical-source 和 scaling 结果，并在其后追加 biological anchor 与新对照。02 的 cancer-type 结果改称 `lineage recoverability` 诊断，不作为 biological utility。03 不把 02 的 RDS 作为运行时输入，也不写入 02 的缓存或图表目录。

新增联合终点：

- biological anchor performance 相对 Direct 的变化；
- technical-source/assay/platform excess 的变化；
- worst-cohort performance 是否恶化；
- 低标签量下的性能变化；
- utility 与 effective rank 的 Pareto 关系。

用预先定义的判读矩阵区分：selective invariance、task-aligned reorganization、indiscriminate smoothing 和纯信息损失。单项 p-value 不替代组合证据。

### 加入 cohort 结构和 marginal contribution 对照

在固定 query set 下，先固定 base bank，再一次加入候选 cohort，计算：

$$
\Delta U_c(B)=U(B\cup c)-U(B),\quad
\Delta T_c(B)=T(B\cup c)-T(B),\quad
\Delta G_c(B)=G(B\cup c)-G(B),\quad
\Delta R_c(B)=R(B\cup c)-R(B).
$$

其中 `U` 以 biological-anchor utility 为主，`T` 为技术泄漏，`G` 为几何/稳定性，`R` 为冗余。候选 cohort 尽量按样本量、平台、输出 block 宽度、pseudo-label entropy、submodel quality 和缺失基因率配对。

另设真实 cohort bank、匹配随机 pseudo-cohort bank 和 shuffled pseudo-subtype label 三类机制对照。真实 02 元数据可支持的部分进入主层；没有平台/来源证据的完整矩阵新增 cohort 只进入 biology-only 的边际效用探索。

这一步对研究者意味着：03 不只问“cohort 越多是否越好”，而是直接问“加入这一类新队列后，生物学效用增加了多少、技术泄漏是否下降、代价是多少”。

### 用模块化方式扩展 `R/ablation.R`，保持 02 兼容

建议只在 `R/ablation.R` 增加内部模块，并将新能力设为 opt-in：

- 增加可选的 `biology_data`/biology 配置入口，默认 `NULL` 或 `enabled = FALSE` 时完全保持 02 的 `representation` 行为；不改变现有参数默认值和旧结果字段。
- 增加数据对齐、signature scoring、coverage audit、cross-fitted readout、anchor-level inference、marginal cohort contribution 和 biology manifest 的内部 helper。
- 03 通过 `biology = enabled` 调用这些 helper；复制到 03 的旧分析继续走原有路径，02 原目录中的 `ablation-result.rds`、`cohort_scaling.rds` 和测试合同不被覆盖。
- 若新增入口属于公开参数，更新 roxygen 与生成的 `man/ablation.Rd`；若仅为内部 helper，则不引入新的 S4 类或公共 API。
- 缓存键必须包含完整矩阵哈希、anchor manifest 哈希、sample-key hash、bank design hash、readout 配置和随机种子；任何缓存不匹配都重新生成或明确失败。

这一步对研究者意味着：02 是稳定的阶段性成果，03 是在其旁边增加新的证据层，而不是把已经得到的结果替换掉。

## 风险与待确认事项

- **PAM50/CMS 来源：**先确认本地是否已有带版本和出处的冻结 gene list/分类器；若没有，新增最小 manifest 并单独记录来源，不临时从结果反推标签。
- **签名覆盖不均：**不同 cohort 的基因数和平台差异很大；采用预先声明的覆盖阈值和 sensitivity range，不能为了保留某个结果事后调阈值。
- **平台/来源缺失：**完整矩阵的额外 cohort 可能没有 02 工作簿级别的 technical metadata；它们不进入主 technical leakage 因果比较。
- **输入基因循环性：**与 CCS 32 genes 或 Direct gene-pairs 重叠的 anchor 可能夸大一致性；主结论必须提供 disjoint-gene 版本。
- **计算量：**全矩阵对齐、150 modules、多个 RP seed、OOF 和多 anchor 会显著增加运行时间；先缓存按 cohort 的 full-expression subset 和 anchor score，再按固定 query 复用。
- **多重比较：**120 个 exploratory signatures 会产生大量检验；主 anchor 预先限量，探索性结果统一 FDR，并与主结论分开。
- **复制后结果漂移：**复制完成后应保存 02→03 的源文件清单和复制时 Git hash；03 自己运行产生的 manifest/config/data hash 单独记录。若 03 对复制的旧分析做了必要调整，应在 03 报告中标明差异，不能静默声称与 02 数值完全相同。
- **成功标准：**在执行前冻结“生物 anchor 非劣效、技术泄漏下降、最差 cohort 不恶化、低标签量至少一项改善”的组合判据；若结果不满足，应如实报告 d1 的权衡或信息损失。
