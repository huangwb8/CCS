# `ablation()` 优化实施计划

## 通俗解释：究竟发生了什么

当前 `R/ablation.R` 已经能够执行多类消融分析，但输入准备、实验调度、科学计算、缓存、文件输出和 `targets` 适配长期叠加在同一套实现中。结果是：单次运行可以工作，但长时间运行中断后不一定能精确恢复，新增实验也容易扩大公共接口和回归范围。

本计划不把 `ablation()` 拆成一组需要用户记忆的新函数，也不立即拆分多个 R 文件。计划保留一个公共 `ablation()` 和一个 `R/ablation.R`，在函数内部建立四个明确阶段：

```text
context → plan → runner → result
```

普通用户继续调用一次 `ablation()`；`targets` 按 `step` 调用同一个函数的不同阶段。用户只需要指定缓存总目录 `cache.root`（可选），程序负责创建子目录、生成内容键、保存节点缓存和恢复状态。

## 专业判断：问题在哪里

当前实现有三个相互关联的边界问题：

- 输入准备和实验执行没有形成稳定的、可复用的上下文对象；
- `targets` 入口目前可以把多个计算节点包进一个大 target，且内部 checkpoint 可能写入临时目录，中断后失去恢复价值；
- `output.dir` 同时承担正式结果和中间缓存职责，旧 layered 路径保存了阶段文件但没有形成可验证的恢复合同。

因此本次重构的重点不是重新实现统计方法，而是建立稳定的数据合同、节点粒度和持久化边界，同时保证科学结果、参数默认值、随机数语义和既有普通调用保持等价。

## 目标

- 保留单一公共入口 `ablation()`，默认 `step = "all"`，兼容现有普通调用。
- 在同一个 `R/ablation.R` 内建立 `context`、`plan`、`runner`、`result` 四层职责。
- 让普通入口和 `ablation-03` 的 `targets` 入口消费同一套内部阶段实现。
- 用 `step` 控制生命周期阶段，而不是新增一组 `ablation_*` 公共函数。
- 新增可选 `cache.root` 参数；只由它指定缓存总路径，子目录和文件由程序管理。
- 将正式交付物 `output.dir` 与可复用的中间缓存彻底分离。
- 中断后只重算未完成或因依赖失效的节点；已完成节点通过内容键安全复用。
- 保持分析方法、默认参数、随机种子派生规则和结果字段的科学等价性。
- 通过包检查、缓存恢复测试和 `test/ablation-03` 串行验收后，再考虑版本门禁要求的后续动作。

## 不在本次范围内

- 不改变消融实验的科学问题、统计定义、指标含义或默认比较对象。
- 不同时重写四个实验的算法实现。
- 不引入新的并行框架；先建立可靠的串行节点恢复，再评估受控并行。
- 不把报告渲染、`SUCCESS`、stage receipt 或 targets store 管理塞回科学计算核心。
- 不新增未经验证的公共导出函数；现有 targets-facing 导出函数应在迁移完成后评估保留、降级或移除。
- 不修改 `DESCRIPTION` 的版本号、Git tag 或发布文件，除非项目负责人在满足全部门禁后另行授权。

## 目标架构

### 单一公共入口与阶段调度

`ablation()` 保留现有主要输入参数，并在兼容位置增加 `step`、`input` 和 `cache.root` 相关能力。`step` 只表达生命周期，不把具体实验名称和节点名称硬编码成大量字符串。

稳定阶段集合为：

- `all`：普通用户的一站式调用；
- `context`：验证和规范化输入，构造共享分析上下文；
- `plan`：从上下文和配置生成确定性的实验/节点/job 清单；
- `run`：执行一个 plan 节点或 job；
- `result`：校验、汇总节点输出并构造最终 `CCSAblation`。

阶段输入应采用明确的数据对象或统一的 `input` 载荷，避免把 `context`、`plan`、`job`、`results` 都扩张成长期公共参数。每个 step 必须验证输入类型、必需字段和禁止组合，并在错误信息中说明正确的调用边界。

### Context

Context 是一次分析的固定输入世界，至少包含：

- 已验证的 CCS 对象引用和输入来源身份；
- 对齐后的表达、Direct-GSClassifier、Cohort-d1 矩阵及样本 metadata；
- feature/module manifest 和 endpoint eligibility；
- 规范化配置、seed plan、schema 版本；
- `context.key`、输入哈希和运行时信息；
- 解析后的 `cache.root` 与缓存布局信息。

Context 只做一次输入准备，不执行所有实验，不写正式报告，不隐式依赖全局工作目录。

### Plan

Plan 是可审计的执行清单，至少描述：

- 实验、节点和 job 的稳定 ID；
- 节点之间的依赖和 parent key；
- 每个节点的参数快照、seed 和预期结果合同；
- learning curve、scaling 等可恢复任务的最小 job 粒度；
- 不可执行任务及其明确排除原因。

Plan 必须是可序列化的普通对象，不保存闭包、临时路径或隐含环境。

### Runner

Runner 消费 context 加一个 plan 节点/job，完成一次实际科学计算并返回可序列化的局部结果。Runner 不负责选择完整工作流、不写 targets store、不创建正式报告，也不依赖尚未声明的全局 RNG 状态。

当前 `.ablation_experiment_*()`、retrieval/readout/learning-curve/decoder 等实现应逐步收敛到这一职责；第一轮只移动调用边界和持久化边界，不同时改算法。

### Result

Result 负责验证节点完整性、按 plan 合并局部结果、生成 paired contrasts、summary、audit、diagnostics 和 provenance，并构造最终 `CCSAblation`。Result 不重复执行已完成 runner，也不把缓存路径误当成科学结果身份。

## 缓存与路径设计

### `cache.root` 与 `output.dir` 的职责分离

- `output.dir`：面向审阅和报告的正式产品，如 manifest、audit、最终 RDS 和 CSV。
- `cache.root`：中间矩阵、节点 checkpoint、job checkpoint、状态文件和缓存清单。

用户只指定缓存总路径，例如 `D:/cache/ccs-ablation`；程序在其下建立版本化、内容键控的子目录。默认值应指向项目约定的隐藏缓存位置，并经过可写探针验证；默认路径必须被忽略，不得污染源码仓库。

缓存布局至少应区分：

- context/preparation artifacts；
- plan；
- 节点和 job value；
- `running`/`complete` 状态；
- locks 或并发冲突记录；
- cache manifest 和失效原因；
- targets store（与正式结果目录分开）。

绝对路径不进入科学 cache key；迁移 `cache.root` 不应导致科学结果无理由失效。缓存 manifest 仍需记录实际路径、包版本、R 版本、schema 和来源哈希。

### 缓存有效性合同

每个可复用节点必须绑定实际决定结果的：

- 上游 context/plan key；
- 输入值和样本身份；
- 节点参数与 seed；
- 算法 revision/schema；
- 相关依赖包版本；
- 输出 value hash。

只接受同时满足 state、key、文件完整性、value contract 和 hash 校验的 `complete` 条目。`running`、截断文件、旧 schema、父节点变更和不完整 job 必须安全重算。并发运行相同 key 时应避免重复计算，或至少保证只有一个结果能提交为有效完成状态。

## 实施顺序

### 先冻结当前行为和基线证据

建立小型、固定 seed 的 characterization fixture，记录当前四类实验的结果结构、关键 metrics、审计字段、输入键和缓存命中语义。先确认现有 working tree 中的 ablation-03 迁移改动边界，不覆盖未提交用户改动。

完成标准：同一 fixture 的重复运行结果、schema、关键哈希和现有测试基线均可复现；失败时先修复基线问题，不进入结构迁移。

### 在同一个文件中划分四层边界

在 `R/ablation.R` 内增加清晰的内部区段和私有调度函数，但不拆分多个 R 文件，也不立即改写科学算法。把现有输入准备、实验计划、执行和汇总调用分别收口到 context/plan/runner/result 边界。

完成标准：普通 `step = "all"` 仍得到与基线科学等价的 `CCSAblation`；每个阶段可独立做结构校验；没有新增公共 namespace 污染。

### 引入 `cache.root` 和运行时配置

在 context 建立时一次性解析 `cache.root`、默认路径、output 路径、targets store 路径和 cache schema。后续阶段从 context 继承运行时配置，禁止各实验函数自行拼接绝对路径。

完成标准：用户指定路径和默认路径都能创建、复用、迁移和恢复；正式输出不与缓存混放；不可写路径和路径冲突能早返回；现有 `output.dir` 行为不会被静默改变。

### 把持久缓存从临时目录迁移到节点级持久目录

保留 Direct、native geometry 和现有节点缓存的有效内容键思路，但把长期恢复所需的 value/state 放入 `cache.root`。移除 `targets` 入口对临时工作目录作为长期 checkpoint 的依赖。把 learning curve 和 scaling 拆到 plan 规定的 job 粒度，并让单个 job 可独立命中或重算。

完成标准：模拟中断后重新运行时，已完成节点和 job 不重复计算；`running` 状态不会被误认为成功；被修改的上游只使相关下游失效；缓存损坏会安全回退到重算。

### 让 targets 真实反映 plan，而不是先算大列表再拆字段

调整 `test/ablation-03/_targets.R`，使 context、plan、节点和 job 成为真实依赖；报告只消费已完成的结果对象。`targets` store、`cache.root` 和正式报告目录保持清晰边界。暂不引入超出串行验收范围的并行调度。

完成标准：查看 manifest 可以看到独立节点依赖；只修改报告或单个节点配置时，不会重新执行无关节点；中断恢复不依赖 `source("R/ablation.R")` 或 `CCS:::`。

### 收敛公共 API 和文档

以单一 `ablation()` 为正式调用入口，评估当前 `ablation_*` targets-facing 导出函数的迁移兼容策略。优先保留兼容期内部转发或明确弃用说明，待 targets 已完全消费新入口并通过验收后再删除不必要导出。同步更新 `NAMESPACE`、roxygen 文档、`docs/ablation.md`、`test/ablation-03/README.md` 和 `[Unreleased]` changelog。

完成标准：普通用户文档只需记住 `ablation()`；targets 文档能说明 step/input/cache.root 合同；不存在与实现不一致的旧入口说明。

## 验收与验证矩阵

- 输入合同：缺失对象、错位样本、坏 metadata、非法 step/input 和不可写 `cache.root` 均早返回且错误明确。
- 科学等价性：固定 fixture 下比较旧基线与新架构的关键 metrics、结果表结构、seed、manifest 和 audit；允许的差异必须有记录。
- 缓存命中：完全相同 context/plan/node/job 必须命中，不重复计算。
- 缓存失效：逐一修改输入值、metadata、参数、seed、算法 revision、依赖版本和 parent key，要求对应节点 miss，下游按依赖失效。
- 中断恢复：在 Direct、retrieval、learning curve job、scaling job 和 result 汇总的不同阶段模拟终止，确认重启只运行未完成部分。
- 损坏恢复：截断 RDS、错误 state、错误 key、value hash 不匹配和旧 schema 均不能命中。
- 路径隔离：指定多个 `cache.root` 时结果不互相覆盖；移动缓存根目录不会改变科学 key；正式 output 与缓存不混写。
- targets：`tar_manifest`、串行 `tar_make`、单节点失效和报告重渲染均只触发必要依赖。
- 包验证：按项目约定使用 `C:\R\R-4.3.1` 完成 `devtools::document()`、`R CMD build`、`R CMD check` 和相关场景脚本；完成 `test/ablation-03` 串行验收后再进行任何授权的 patch 版本门禁。
- 审计：交付前运行 `python -m bac --root . --bac-file docs/contribution.bac verify --json`，并在变更摘要中说明缓存策略、验证范围和未覆盖限制。

## 风险与待确认事项

- 当前 working tree 已有 ablation-03 targets 迁移改动；实施前需要先确认哪些未提交改动属于本次基线，避免把用户工作误当成可重写代码。
- 大型表达矩阵放入 context 可能增加 targets 序列化成本；必要时应让 context 保存经过 hash 验证的 artifact 引用，同时保留可恢复的构建合同。
- 多进程同时请求同一 cache key 需要锁或明确的去重策略，否则可能出现重复计算；原子写入只能防止文件损坏，不能自动防止重复计算。
- 缓存命中必须优先保证科学正确性，不能为了减少重算而放宽 reference 数值、metadata、算法版本或依赖身份的校验。
- 本计划只规定结构和验收，不授权发布、版本递增、远程写入或删除历史缓存。
